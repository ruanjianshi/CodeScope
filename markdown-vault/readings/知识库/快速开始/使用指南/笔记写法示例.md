# 笔记写法示例

这份文档列出知识库里**已经支持**的写法。照着写，页面立刻就有「内容感」——
纯文字堆在一起是最容易显得空洞的。

## 一、文字标注

| 写法 | 效果 | 说明 |
| --- | --- | --- |
| `{红\|文字}` | {红\|文字} | 指定颜色文字。九色：红 橙 黄 绿 青 蓝 紫 粉 灰 |
| `==文字==` | ==文字== | 黄底高亮 |

> 表格里写彩色文字，分隔符要写成 `{红\|文字}` —— 因为 Markdown 会**先按 `|` 切表格列、再解析行内语法**，
> 裸的 `|` 会把这一行切成两列（本页这个表格原先就踩了这个坑）。
> 正文和引用块里不用转义，直接写 {红|文字} 就行。

效果示例：函数指针 {红|指向函数的指针}，而 ==指针函数== 是「返回指针的函数」，别混。

## 二、提示框

两种语法，看你写在哪。**笔记正文用 A**，知识库站点用 B。

### A. 笔记正文 / 阅读器：`> [!类型] 标题`

> [!note] 笔记
> 记录值得留下的想法。

> [!info] 信息
> 补充一点背景，帮助理解上下文。

> [!warning] 注意
> 容易踩的坑写这里。

> [!important] 重点
> 必须记住的那一条。

支持 17 种语气，每种颜色不同，右下角还有一个对应的浅色水印：

| 类型 | 写法 | 用在 |
| --- | --- | --- |
| 笔记 | `> [!note]` | 记录想法 |
| 信息 | `> [!info]` | 补充背景 |
| 待办 | `> [!todo]` | 下一步做什么 |
| 提示 | `> [!tip]` | 经验之谈 |
| 成功 | `> [!success]` | 做对了 / 通过了 |
| 问题 | `> [!question]` | 待确认的疑问 |
| 警告 | `> [!warning]` | 容易踩的坑 |
| 重点 | `> [!important]` | 必须记住 |
| 危险 | `> [!danger]` | 不可撤销的操作 |
| 缺陷 | `> [!bug]` | 已知问题 |
| 失败 | `> [!failure]` | 跑不通的结果 |
| 示例 | `> [!example]` | 举一个例子 |
| 摘要 | `> [!abstract]` | 一段的总结 |
| 引用 | `> [!quote]` | 原文照录 |

别名也认：`hint` 同提示，`check` / `done` 同成功，`caution` / `attention` 同警告，`error` 同危险，`summary` / `tldr` 同摘要，`cite` 同引用。

> [!tip] 标题可以自己写
> `> [!note] 随便什么标题` —— 右方括号后面那截就是标题，不写就用默认的中文名。

### B. 知识库站点：`::: tip 标题`

知识库是 VitePress 渲染的，**暂时不认 `> [!类型]`**（会显示成普通引用），所以站点里用三冒号容器：

::: tip 小技巧
`::: tip` 用来写补充说明、经验之谈。
:::

::: warning 注意
`::: warning` 用来写容易踩的坑。
:::

::: danger 危险
`::: danger` 用来写「这么做会出事」的地方。
:::

::: details 点开看展开内容
`::: details 标题` 写可折叠内容，默认收起 —— 长代码、大段日志用它，正文就不会被撑得很长。
:::

## 三、代码块

**带文件名**：围栏后面用方括号写文件名。

**指定行高亮**：大括号里写行号，支持 `2`、`2,5`、`2,5-7`。

```c{2,5-6} [main.c]
int main(void) {
    int *p = NULL;          // 这一行被高亮
    p = (int *)malloc(4);
    if (!p) return -1;
    *p = 42;                // 这两行也被高亮
    free(p);
    return 0;
}
```

## 四、代码组（多语言 / 多方案对照）

同一件事的不同写法并排放，点标签切换：

::: code-group
```c [指针常量]
int *const p = &a;   /* 指向不可改，值可改 */
```
```c [常量指针]
const int *p = &a;   /* 值不可改，指向可改 */
```
:::

## 五、表格

| 概念 | 含义 |
| --- | --- |
| 指针常量 | 指针本身是常量，不能改指向 |
| 常量指针 | 指向的内容是常量，不能改值 |

## 六、徽章

给标题或条目加状态标记：<Badge type="tip" text="已验证" /> <Badge type="warning" text="待补充" /> <Badge type="danger" text="有坑" />

## 七、引用与分割线

> 引用一段原文、标准里的描述，或者别人的说法 —— 和自己的想法区分开。

## 八、暂时**不要**用的写法

这两条会让构建失败或渲染成乱码，等装了插件再说：

- **脚注**：写成 `[^1]` 会**直接报死链、整个站点构建失败**（不是静默忽略，很坑）。
- **任务列表**：写成 `- [ ]` 会原样渲染成字面的 `[ ]`，不会变成勾选框。

## 九、写笔记的一点建议

1. **术语用加粗或标注**：正文里 `**术语**` 会被自动收进右侧「本页速览」，长文才有导航。
2. **一段一个点**：每段以「术语：说明」开头，右侧速览就会自动成目录。
3. **能画就别写**：内存布局、继承关系、调用链，一张图胜过十行字。
4. **代码块带文件名和行高亮**：回头再看时，一眼知道在说哪一行。
