# 接口化程序

**函数指针**：{红|一个指向函数的指针}。 int\* (\*add)(int, int) = \&add;

**指针函数**：一个函数的返回体是指针。int\* add(int a){static int b = a; return \&b)};

指针的大小：指针的大小只与电脑的位数有关：32位系统4字节，64位系统八字节大小

静态变量：全局持久+局部隐藏

全局变量：公开持久

sizeof与strlen区别：前者是运算符，计算所占内存大小。后者为函数，计算字符串长度

数组指针：一个指向数组的指针。int a\[10]; int (\*p)\[10] = \&a; a与\&a地址一样，步长不同

指针数组：一个里面元素都是指针的数组。int\* a; int\* p\[10] = {a};

指针常量：指针是一个常量，可以修改指向值，但不可修改指向。int\* const p = \&a;

常量指针：一个指向常量的指针，可以修改指向，但不可修改值。const int\* p = \&a;

大小端：高字节在低位为大端，低字节在低位为小端。0x12345678,0x78开头为小端。

如何判断系统大小端：char a = 0x12345678, printf(”%x/n”,a)。0x78则为小端存储。

**`malloc` 是 C 语言的库函数，只负责从堆里划出一块原始内存，不管构造。**

**`new` 是 C++ 的运算符，不仅分配内存，还会调用对象的构造函数进行初始化。**

内联函数（inline）：**内联函数是一种“请求编译器把函数体直接展开在调用处”的优化手段，用代码膨胀的代价换取函数调用开销的消除。内联函数必须定义在头文件中。**

strcpy. strcmp. strcat. memcpy. :字符串复制、对比是否相同、拼接、任意类型复制。

程序五个段：代码段（只读）、数据段（已初始化）、BSS段（未初始化）、堆（用户）、栈

c→exe: 预处理(.i)→编译(.s)→汇编(.o)→链接(.exe)

```
⚙️ 四步流水线
  预处理(.i) → 编译(.s) → 汇编(.o) → 链接(.elf)

📝 每步做什么
  预处理：头文件展开 + 宏替换 + 条件编译
  编译：  C → 汇编（语法分析+优化）
  汇编：  汇编 → 机器码 + 符号表
  链接：  合并目标文件 + 库 → 可执行文件（解析符号，重定位）

🛠️ 生成文件一览
  main.c → main.i → main.s → main.o → program.elf (.bin/.hex)
```

交叉编译：一个平台编译出另一个平台的可执行文件。

内存分配：

1. 静态存储器分配：全局变量，静态变量
2. 栈上分配：函数中的局部变量
3. 堆上分配：malloc,new

union联合体：共用一块内存，且大小由最大元素内存决定。

野指针：指向不可用内存的指针。

**悬垂指针**：特指**曾经有效，但目标内存已被释放或回收**的指针（如 free 后未置空，返回局部变量地址）。

```markdown
   野指针四大来源：
   ① 未初始化       int *p; *p=5;     → 随机地址 💥
   ② free未置空     free(p); *p=5;   → 已回收的房 💥
   ③ 返回局部地址    return &a;       → 退租的栈房 💥
   ④ 越界操作       arr[10] = 5;     → 踩隔壁的地 💥
```

```markdown
🔄 宏 = 纯文本替换，不是传值

❗ 两大陷阱：
   1. 参数不加括号 → 运算符抢优先级
      #define BAD(x)  x*x
      BAD(1+2) → 1+2*1+2 = 5 ❌

   2. 整体不加括号 → 外部运算符吞噬
      #define BAD2(x) (x)+(x)
      3*BAD2(4) → 3*4+4 = 16 ❌

🛡️ 黄金防御：
   #define GOOD(x)  ((x) * (x))
   #define MULTI_SWAP(a,b) do{...}while(0)
```

**`#define` 是预处理阶段的纯文本替换，见啥换啥，不管语法。**

**`typedef` 是编译阶段创建类型别名，编译器全程理解，有作用域和类型检查。**

内存泄漏：**向堆申请了一块内存，用完后没有归还，程序又弄丢了这块内存的地址，导致这块内存永远无法再被使用。**

内存对齐：**CPU 访问内存时，希望数据的起始地址是自身大小的整数倍，否则需要多次读写才能拼出数据，性能下降，甚至在某些架构上直接崩溃。**

取消内存对齐：#pragma pack(1)取消内存对齐，#pragma pack()恢复对齐。

```markdown
🏢 数组名 vs 📝 指针

📌 本质：
   数组名 = 带长度信息的地址常量（大楼）
   指针   = 存地址的变量（纸条）

📌 关键差异：
   sizeof(数组) → 整个数组大小
   sizeof(指针) → 4/8 字节

   &数组 → 数组指针 (指向整个数组)
   &指针 → 指针的指针

   数组名不可改，指针可改

📌 退化规则：
   函数参数 int arr[] → int *arr (退化为指针)
   sizeof 在函数内失效
   & 作用于函数参数不再得到数组指针

📌 经典陷阱：
   char *p = "abc";  p[0]='A';  → 💥 只读段
   char a[]="abc";   a[0]='A';  → ✅ 栈上可改

🔑 一句牢记：
   数组名是“完整的家”，指针只是“地址纸条”。
   多数时候数组名变成纸条用，但 sizeof 和 & 时会露馅。
```

浅拷贝：只复制指针的值，多个对象共享一块动态内存，使用简单类型无需管理对象

`双重释放、野指针、意外联动修改`

深拷贝：复制指针指向的内存，多个对象各自拥有独立内存空间

| **维度**        | **堆 (malloc/free)**       | **自由存储区 (new/delete)**                |
| ------------- | ------------------------- | ------------------------------------- |
| **语言**        | C 标准库                     | C++ 运算符                               |
| **分配方式**      | `void* p = malloc(size);` | `T* p = new T(args);`                 |
| **释放方式**      | `free(p);`                | `delete p;`                           |
| **是否调用构造/析构** | ❌ 不调用                     | ✅ 调用构造函数 / 析构函数                       |
| **返回类型**      | `void*`，需强制转换             | 正确类型指针，类型安全                           |
| **内存大小**      | 需手动计算字节数                  | 编译器自动计算 `sizeof(T)`                   |
| **可重载**       | 不可（除非自己实现 malloc）         | 可类内或全局重载 `operator new`               |
| **失败行为**      | 返回 `NULL`                 | 抛出 `std::bad_alloc` 异常（默认）            |
| **底层区域**      | 通常就是自由存储区 / 同一内存池         | 默认调用 `operator new`，内部可能用 `malloc` 实现 |

```markdown
指针 是一个变量，存储着另一个变量的内存地址，可以改变指向，可以指向空，可以多级嵌套。
引用 是另一个变量的别名，一旦绑定就不能再更改，从语法上就像一个解引用后的指针，但不能为空，不能多级引用。
```

“拷贝地址和拷贝值”：拷贝地址可以通过地址找到所包含的值一或者所指向的地址，通过地址所修改的值或则所指向的地址，才是真正的修改，同步。函数的形参本质都是值拷贝。

DFS 的核心是**递归**，它沿着一个方向不断深入，直到无路可走，再回溯到上一个分岔口，尝试另一个方向。

BFS 的核心是**队列**，它先把起点周围的节点全部加入队列，然后按层处理。

extern “c” : C++中告诉编译器以C语言的方式处理代码（防止C++名字修饰）（跨语言链接）

```markdown
🧩 内存碎片 = 空闲内存不连续，大车无法停进分散的小空位

📌 两大类型：
   外部碎片 → 空闲块之间穿插已用块，形成“空洞”
   内部碎片 → 分配块内部浪费的空间（对齐/固定大小）

💥 危害：
   malloc 失败、实时性破坏、内存利用率低
   嵌入式长期运行后可能突然崩溃

🛠️ 常用对策：
   内存池（固定大小）→ 无外部碎片
   伙伴系统（合并相邻）→ 减少外部碎片
   Slab缓存 → 对象复用
   静态分配 → 零碎片（最彻底）

⚡ 嵌入式实践：
   - 优先静态分配或内存池
   - FreeRTOS 用 heap_4 支持合并
   - MISRA 禁止动态分配
   - 监测最大连续空闲块预警

🔑 一句牢记：
   动态分配是把双刃剑，频繁不同大小分配产生碎片，
   内存池固定大小无惧外部，静态分配彻底杜绝碎片。
```

重写memcpy()时就需要考虑地址重叠

static作用：“改变生命周期” 或者 “改变作用域”。

宏定义的作用范围仅限于当前文件。 而默认状态下，const对象只在文件内有效，当多个文件中出现了同名的const变量时，等同于在不同文件中分别定义了独立的变量。 如果想在多个文件之间共享const对象，必须在变量定义之前添加extern关键字（在声明和定义时都要加）。

volatile关键词的作用是影响编译器编译的结果，用volatile声明的变量表示该变量随时可能发生变化，与该变量有关的运算，不要进行编译优化，以免出错。

1）中断服务程序中修改的供其它程序检测的变量需要加volatile；

2）多任务环境下（如多线程）各任务间共享的标志应该加volatile；

3）存储器映射的硬件寄存器通常也要加voliate，因为每次对它的读写都可能有不同意义。

如果此时类里有一个或多个虚函数，那么需要加1个虚指针空间，如果还是虚继承，那么需要再加1个虚指针空间，最多就2个虚指针空间。

**普通继承**：每个派生类直接包含基类的子对象，多代继承下可能有多份基类副本。

**虚继承**：只保留一份共享的基类子对象，解决“菱形继承”导致的数据冗余和二义性。
