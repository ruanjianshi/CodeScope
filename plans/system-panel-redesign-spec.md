# 本机管家 · 重构设计规范（v1，2026-10-29）

> 依据：对现有实现（`src/system-panel.js` 4,020 行 / `lib/system-panel.js` 2,476 行）的实际观察。
> 目标：**信息层级正确 + 一套图形语言 + 数据可信**。不是推倒重写，是重排版面与统一语言。

## 1. 首屏信息层级（概览页，必须按此顺序）

```
┌ 顶部一行：健康状态条（唯一的"结论"层） ─────────────────────────────┐
│ ● 正常 / ⚠ 2 项需要注意 / ⛔ 需要处理    三到四条**具体问题**，可点跳转 │
└──────────────────────────────────────────────────────────────────┘
┌ 左（主区，占 2/3）────────────────┬ 右（信息栏，占 1/3）────────────┐
│ ① 资源水位（紧凑横条，不是环）    │ 系统信息（8 行以内，可用"更多"展开）│
│    CPU / 内存 / 主磁盘 三行       │                                  │
│    每行：名称 · 条 · 百分比 · 一句话说明                            │
│                                  │ 开机时长、CPU 型号、内存、主盘      │
│ ② 趋势（两张主图，可切换范围）    │                                  │
│    CPU 与内存默认显示；流量/IO    │ 常用应用（最多 6 个，超出收进"更多"）│
│    收进「更多指标」折叠           │                                  │
│                                  │                                  │
│ ③ 需要注意（最多 3 条 + 查看全部）│                                  │
└──────────────────────────────────┴──────────────────────────────────┘
```

**规则**

- **KPI 数字不再做成大卡片**。进程数 / 端口数 / 启动项 / 应用数 → 变成「分区入口」的一行小字（`621 进程 ›`），点击进对应分区。它们不是概览的主角。
- **环形表全部废弃**，统一改用**水平水位条**：同一条基线、同一套颜色语义、更省纵向空间、读数时条长与百分比直接对应。
- **颜色语义统一 3 档**：正常（`--ok` 绿）/ 注意（`--warn` 琥珀，≥75%）/ 告警（`--bad` 红，≥90% 或不可用）。**不出现第 4 种颜色**。
- **不可用的指标直接不渲染那一行**，在「需要注意」里给一句说明（例：`温度不可读（Apple Silicon 无 SMC 暴露）—— 可用 smctemp 查看`）。**不允许用「—」占位**。
- **外接盘不进健康总评**，只在「需要注意」里出现一条：`UDISK64 已用 100%（330 MB 可用）›`。健康总评只覆盖 CPU / 内存 / 主磁盘。

## 2. 视觉语言（一套，两类元素）

只允许两种容器：

1. **区块（band）**：无边框、无阴影、无圆角卡片气。用 `1px` 的极淡分隔线 + 24px 纵向间距切分。标题 11px/字重 650/字距 .04em + 左侧 2px 强调竖条。
2. **行（row）**：表格与列表统一行高 30px，hover 用 `--surface-hover`，不画竖线。

禁止：卡片阴影、圆角超过 10px、图标网格、渐变背景。

排版：正文 12px / 次要 11px / 数字用等宽 `var(--mono)` 且右对齐；标题不用彩色（只有区块竖条用强调色）。

## 3. 导航（7 → 5）

| 新分区 | 合并了什么 |
| --- | --- |
| **概览** | 原 home |
| **进程与端口** | 原 monitor + runtime 里的端口/服务 |
| **存储与清理** | 原 storage + 原 files（浏览与占用合并，因为二者都是"空间"问题） |
| **软件与启动** | 原 software + runtime 里的开机启动项/开发环境 |
| **设置** | 原 settings |

⚠️ **视图 id 不要重命名**（`processes` / `files-usage` 等仍被命令面板与深层链接引用），只改导航的分组与标签。

## 4. 数据可信（必须一并修）

1. 「常驻服务」→ 改标签为 **「Homebrew 服务」**，并给 title 说明"仅统计 brew services 托管项，不是系统全部常驻进程"。若数量为 0，这一项在概览里不显示。
2. 温度不可用 → 不渲染水位条；在「需要注意」里给一条可操作说明。
3. 外接盘满 → 不进健康总评，只进「需要注意」。
4. 健康总评的文案必须与它覆盖的范围一致：写「CPU、内存、主磁盘正常」，而不是笼统的「一切正常」。

## 6. ⚠️ 方向修订（2026-10-29，用户新指令）：程序员风格 · 简朴 · 纸质化

用户后续要求：「程序员风格的那种，简朴，纸质化风格」。
这是对第 1 节调色板方向的**修订**，但**第 2/3/4 节的结构与动效规则全部保留**（细线、10px 圆角以内的克制、等宽只给数字、区块/卡片两级容器）。

### 6.1 纸质调色板（实现方式：**在这个面板容器内覆盖令牌**）

面板自带容器类（如 `.lw-inpanel`），所以在它上面**局部覆盖主界面变量**即可，不需要改 `app.css`，也不会外溢到其它视图：

```css
.lw-inpanel {
  --bg: #f6f3ea;          /* 纸底：暖白，不刺眼 */
  --panel: #fbf9f3;       /* 卡片：比纸底再亮一档 */
  --panel2: #f1ede1;      /* 次级面：表格斑马纹、内嵌块 */
  --border: #d9d3c4;      /* 细线：像印刷品的 hairline */
  --text: #221f1b;        /* 墨字 */
  --dim: #6c6659;         /* 次要墨：注释、元信息 */
  --accent: #2f5d46;      /* 墨绿：唯一的强调色，像钢笔水 */
  --ok: #3f7a4f; --warn: #9a6b1f; --err: #a23b2a;
  --lw-shadow: none;      /* 纸质不用投影 */
}
```

### 6.2 「简朴」的具体含义（否则会退化成空）

- **无阴影、无渐变、无玻璃**。层级只靠：底色差（三档）+ hairline 细线 + 间距。
- **圆角收到 3px**（纸不会圆角），比原来的 6–10px 更硬朗但不尖。
- **强调色只出现在三处**：区块标题左侧 2px 竖条、当前选中项、关键数字。别处一律用墨色。
- **等宽字体回来说得通**（程序员风格）：数字、时间、键位、代码样片段用等宽；中文正文仍用正文字体。
- 去掉满屏 1px 实线框：区块之间只留 **24px 间距 + 一条 8% 灰的 hairline**，不要每块都画框。

### 6.3 动效在纸质风格里的收敛（与第 4 节的冲突怎么办）

第 4 节要求「灵动/动态」，纸质要求「简朴」——两者的交集是：**短、静、只做必要的提示**。

- 保留：hover 底色变化 `var(--mo-1)`、选中态左侧竖条生长 `var(--mo-2)`、区块入场只做 `opacity`（**去掉 translateY**，纸不会飘起来）。
- 保留：数字变化用一次性高亮（背景闪一次纸黄 → 回落），不要滴答滚动。
- **去掉**：卡片抬升 `translateY(-1px)`、按下 `scale(.985)`、过冲曲线 —— 这些是「塑料感/悬浮感」的来源。
- 仍然必须写 `prefers-reduced-motion`：只保留颜色变化。

### 6.4 需要用户确认的一件事（写在这里备忘）

纸质面板是**浅色**的，而 CodeScope 主界面默认是深色 —— 打开面板会是一整块亮色区域。
两种可能：**(a)** 就要这个反差，像「桌面上摊开一本笔记本」；**(b)** 面板跟随 App 主题：App 浅色时才用纸白，深色时用「深色哑光纸」（`#1b1a17` 底 + `#e8e4d8` 字，无阴影无圆角感）。
默认按 **(a)** 实现；若用户选 (b)，只需在 `.lw-inpanel` 上再加一段 `html[data-theme]` 版本。

## 7. ★ 最终方向（2026-10-29 定稿，**覆盖 6.1 / 6.3 中与本节冲突的部分**）

用户最终指令：「**B**（面板跟随 App 主题）+ **不是简朴，需要很好的交互立体感**」。

⇒ 物理隐喻从「平摊的一张纸」改成「**一叠有厚度的纸**」：有层次、有压痕、能拿起来、能按下去。
⇒ 调色板必须做**两套**，由 `html[data-theme]` 切换（App 深色/浅色各自成立）。

### 7.1 两套调色板（局部覆盖在面板根容器上）

```css
/* 浅色：暖白纸 */
html[data-theme=light] .lw-inpanel, html[data-theme=graphite] .lw-inpanel { /* 具体选择器按 App 实际主题名调整 */
  --pp-page:#f4f1e8; --pp-sheet:#fdfbf6; --pp-sheet2:#f7f3e9;
  --pp-ink:#221f1b; --pp-ink2:#6c6659; --pp-line:rgba(34,31,27,.10);
  --pp-accent:#2f5d46;
  --pp-shadow:0 1px 1px rgba(28,24,16,.05), 0 2px 4px rgba(28,24,16,.06), 0 8px 18px rgba(28,24,16,.05);
  --pp-shadow-lift:0 2px 2px rgba(28,24,16,.06), 0 6px 12px rgba(28,24,16,.10), 0 16px 32px rgba(28,24,16,.08);
  --pp-inset:inset 0 1px 2px rgba(28,24,16,.14);
}
/* 深色：哑光墨纸 */
html[data-theme=ocean] .lw-inpanel, html[data-theme=midnight] .lw-inpanel, html[data-theme=forest] .lw-inpanel {
  --pp-page:#14120f; --pp-sheet:#1c1a16; --pp-sheet2:#232019;
  --pp-ink:#ece7db; --pp-ink2:#a49d8e; --pp-line:rgba(236,231,219,.10);
  --pp-accent:#d8c9a3;
  --pp-shadow:0 1px 0 rgba(0,0,0,.5), 0 6px 16px rgba(0,0,0,.42);
  --pp-shadow-lift:0 2px 0 rgba(0,0,0,.5), 0 10px 26px rgba(0,0,0,.55);
  --pp-inset:inset 0 1px 2px rgba(0,0,0,.5);
}
```

⚠️ **主题选择器必须先去 `assets/app.css` 查真实的 `html[data-theme=...]` 取值**（已知至少有 ocean / graphite / midnight / forest / light），不要凭记忆写。
⚠️ 若两套选择器写法太繁琐，允许用**变量间接**：一套基于 `--pp-*` 的规则，两处只定义 `--pp-*` 的值。**不要复制两遍整套样式**。

### 7.2 立体感系统（这是本节的重点，不是可选）

四个明确的层级，每个层级的「厚度」由阴影 + 底色差 + 1px 内高光共同表达：

| 层级 | 用途 | 视觉 |
| --- | --- | --- |
| L0 页面 | 面板底 | `--pp-page`，**无阴影** |
| L1 纸片卡 | 待办/笔记/文件等主卡片 | `--pp-sheet` 底 + `--pp-shadow` + 1px `--pp-line` + **内高光** `inset 0 1px 0 rgba(255,255,255,.7)`（深色版用 `rgba(255,255,255,.04)`） |
| L2 抬起 | 卡片 hover | `translateY(-1px)` + `--pp-shadow-lift`，180ms `var(--mo-out)` |
| L3 浮层 | 对话框 / 抽屉 / 菜单 | `--pp-shadow-lift` 再加一层 `0 24px 60px rgba(0,0,0,.22)`，入场 `translateY(6px)+opacity`，260ms |

**按下**：`--pp-inset` + `translateY(1px)`（不是 scale，纸被按下去是凹的，不是变小）。
**选中**：左侧 3px `--pp-accent` 竖条 + 底色 `--pp-sheet2`（像索引标签）。

### 7.3 动效（立体感靠这几条，不要省）

- 卡片 hover：`transform: translateY(-1px)` + `box-shadow` 换 `--pp-shadow-lift`，`var(--mo-2)` + `var(--mo-out)`。
- 卡片按下：`translateY(1px)` + `--pp-inset`，`var(--mo-1)`。
- 区块/卡片入场：`opacity 0→1` + `translateY(6px)→0`，`var(--mo-3)`，同批 **40ms 步进**（前 8 个）。
- 抽屉/对话框：`translateY(8px) scale(.99) + opacity`，`var(--mo-4)` + `var(--mo-drawer)`（**新增令牌**，已存在）。
- 数字变化：一次性纸黄高亮（背景闪 → 回落 400ms），不要滚动。
- ⚠️ 轮询刷新**不加动画**。
- 必须写 `prefers-reduced-motion`：去掉位移与缩放，保留阴影/颜色/透明度变化（层次感不能丢）。

### 7.4 验收（必须两套主题各截一张）

1. 深色主题（默认 ocean）下：`/tmp/pp-dark-1600.png`。
2. 浅色主题下：点顶栏「主题」→「日光白」后：`/tmp/pp-light-1600.png`。
3. 两张都必须能看出：**至少三层厚度**（页面 / 卡片 / 抬起或浮层）、卡片有内高光、按下是凹进去的。
4. 截图时鼠标**悬停在其中一张卡片上**（用 Playwright `hover()`），让抬起态可见。

## 8. ★★ 修正（2026-10-29）：**结构一律不动，只优化观感与交互**

用户看到第 1 节的产出后明确否定：「**本机管家的概要怎么被修改掉了，我之前那版很好，那种设计**」。
「我需要你给我优化的是 **UI、界面设计、按钮功能**」。

⇒ **第 1 节（信息层级重排）作废**。第 3 节里的「7 → 5 分区」也**暂停**（结构也不动）。
⇒ 保留用户认可的原结构：**顶部 5 张 KPI 卡 + 6 个环形表 + 4 张曲线 + 右栏信息**，一个都不要删、不要换成水位条。
⇒ 本轮只做三件事：**观感、层级表达、按钮与交互**。

### 8.1 观感（只改样式，不改 DOM 结构与信息）

- **间距节奏统一**：区块之间 24px；区块标题与内容 10px；卡片内边距 14px。现在的问题是疏密不匀（KPI 卡很高、右栏又挤）。
- **数字排版**：所有数字用等宽 + `font-variant-numeric: tabular-nums`，右对齐；KPI 主数字加大到 26–30px 但**减小卡片高度**（把「进程」这类标签与副说明压紧）。
- **环形表**：环宽统一（12px），底环与进度环的对比度提高；中心数字 22px 等宽；环下方说明文字统一 11px 两行（现在有的三行，参差）。
- **颜色语义**：正常=绿、≥75%=琥珀、≥90% 或不可用=红，**只这三档**；不可用（温度）改成**灰环 + 「不可用」小字**，不要显示「—」。
- **卡片与层次**（用户要立体感）：卡片 = 底色 + 1px 细线 + 两层柔和阴影 + 顶部 1px 内高光；hover 抬升 1px、阴影加深；按下凹陷（`translateY(1px)` + 内阴影）。圆角 10px。
- **右栏**：把 11 行系统信息压到 **8 行 + 「更多」**；「每核」那排格子改为更小的方块并加 tooltip；常用应用从 8 个降到 **6 个 + 「全部 101 个 ›」**。

### 8.2 层级表达（不改结构，只让层次看得出来）

- 区块标题统一：11px / 650 字重 / 左侧 2px 强调竖条 / 右侧可放一个次要操作（如「查看全部 ›」）。
- 首屏视觉权重：**KPI 卡降一档**（更矮、字号更小、底色更淡），**环形表提一档**（这是要盯的）。只调视觉权重，**不删不换**。

### 8.3 按钮与交互（用户点名要的）

- **KPI 卡变成可点击**：整卡可点 → 跳到对应分区（进程/端口/启动项/应用/Brew 服务）；hover 时显示「查看 ›」；键盘可达（Tab + Enter）。
- **环形表可点击** → 跳到对应详情（内存→性能页、主磁盘→存储页）。
- **「需要注意」每条可点击** → 直达对应分区。
- **刷新按钮**：点击期间显示 disabled + 旋转（`--mo-3`），完成后短暂「已更新 21:17:44」。
- **所有可点击元素的三种状态**：hover（底色/描边变化，`--mo-1`）、active（凹陷或 `scale(.985)`，`--mo-1`）、focus-visible（2px 强调色描边，不能靠 `outline:none` 去掉）。
- 轮询刷新（1.5s）**不加动画**：数字与环长变化用 `transition: 160ms` 平滑，但不要闪烁/脉冲。

### 8.4 验收

1. 截图 `/tmp/sp-polished-1600.png`：必须是**原来的结构**（5 KPI 卡 + 6 环表 + 4 曲线 + 右栏）。
2. 一张 hover 在某张 KPI 卡上的截图（证明抬升与「查看 ›」）。
3. 报告里列出：改了哪些样式值、新增了哪些交互（按钮/跳转/键盘可达）、以及**你没有删掉任何原有元素**的证据（列出原有区块清单逐项打勾）。

## 9. 阶段 2（2026-10-29）：把「文件 / 存储 / 系统 / 软件」四个子页对齐概览页

概览页已完成（第 8 节）。**其余四个分区页仍是旧观感**，本轮把它们拉到同一套语言。

### 9.1 复用已建立的令牌（不要新发明）

`--sp-r`(10px)、`--sp-shadow` / `--sp-shadow-lift` / `--sp-inset` / `--sp-hi`、区块标题 11px/650 + 2px 竖条、三档阈值 75/90、行高 30px、数字等宽 + tabular-nums。

### 9.2 每页只做这些（**不删功能、不改信息结构**）

| 分区 | 现状问题 | 本轮只做 |
| --- | --- | --- |
| 文件 | 表格与工具栏样式与概览页不同源；行无 hover 反馈 | 表格行统一 30px + hover 底色 + 大小/数字等宽右对齐；工具栏按钮三态 |
| 存储 | 占用条是裸 div、区块无层次 | 占用条改 12px 高、圆角 6px、轨道用 `--sp-tint-strong`、填充用强调色（与概览环形表同一语义）；目录列表行 hover |
| 系统 | 表格与开关类控件没有触感 | 开关/按钮统一三态（hover / 凹按 / focus-visible 2px 强调描边）；危险操作（停止 / 卸载）用 `--sp-danger` 区分视觉（**不新增确认逻辑**，只改样式） |
| 软件 | 列表行过密、升级按钮不显眼 | 行高 30px；主操作按钮固定右侧位置；可升级项用琥珀色左侧竖条标记 |

### 9.3 交互（与概览页保持一致）

- 可点击行/按钮：hover 底色、active 凹按（`translateY(1px)` + `--sp-inset`）、focus-visible 2px 描边。
- 表格排序：当前列显示方向箭头，非当前列灰。
- 加载/刷新：按钮 disabled + 旋转（与概览页刷新按钮同一实现）。
