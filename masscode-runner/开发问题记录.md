## 1. LaTeX 预览「编译中…」卡死 / 服务无响应（重点，反复出现）

**症状**：编辑 LaTeX 时右侧 PDF 预览一直「编译中…」，或报「请求超时」；严重时整个服务无响应（Git 面板/阅读 PDF 全部加载不出，TCP 能连、HTTP 无响应）。

**根因**（三层叠加，逐层排除才定位到真凶）：
1. **Git 面板同步调用**：`gitStatus()` 用同步 `execFileSync` 连续执行 6~8 条 git 命令，vault 是含几百 MB PDF 的云盘大仓库，任意一条卡在云盘 IO 就永久阻塞主线程（`execFileSync` 的 timeout 只发信号、仍无限等待进程退出）。
2. **云盘文件同步复制**：`copyLatexResources()` 用 `fs.copyFileSync` 复制工程资源（图片/PDF 等）。iCloud 上**未下载到本地（on-demand）的文件**，`pread` 系统调用永久挂起且不可中断 → 主线程卡死。`sample <pid> 3` 采样确认：`node::fs::CopyFile → uv_fs_copyfile → pread`。
3. **异步复制后遗留无限等待**：`copyFile` 改为异步后不再卡死主线程，但**该请求本身**仍可能永远不返回（线程池 pread 挂起）→ 前端 65s 超时提示，右侧 PDF 永远加载不出。

**修复**（全部在 `server.js` / `index.html`，按层）：
- Git 全链路异步化：新增 `runGit()`（spawn + 硬超时，超时立即 resolve 并 SIGKILL，绝不阻塞事件循环）；`gitStatus()` 改 async；`gitRoot()` 改为**纯文件系统探测**（向上找 `.git`，不执行任何 git 命令）；commit/push/pull/reset/diff 全部 await。
- `copyLatexResources()`：`copyFileSync` → `await fs.promises.copyFile`；`readdirSync/statSync/mkdirSync` → 异步版本（云盘目录枚举同样可能挂起主线程）。
- `latexBibliographyKey()`：目录遍历与 .bib 读取异步化。
- **单文件复制加 10 秒硬超时**（`Promise.race`）：云盘资源拉不下来就跳过该资源继续编译，**编译请求必然结束**，不会无限等待。
- 前端 `api()` 加 **120 秒超时**（`AbortSignal.timeout`）：服务无响应时明确报「请求超时（后端 X 无响应）…」，不再无限「编译中…/运行中…」。

**验证**：
- 虚拟文档编译 0.7~1.2s 出 PDF；真实 vault 项目（含云盘图片）13.8s 内必返回（跳过云盘资源 + 明确失败原因）。
- 编译期间并发访问 root/Git 均 200，服务全程存活。`npm test` 155 通过。

**注意（用户侧）**：iCloud「未下载到本地」的资源是卡死源头。修复后此类资源会 10s 超时跳过并在日志提示「复制超时或失败」；要让图片随编译走，需在访达对资源文件右键「下载」，让 iCloud 拉到本地后再编译。

## 2. 环境检测 / Draw.io 网络探测拖慢「运行中…」

**症状**：环境检测卡 8 秒；首次运行代码前也久等；Draw.io 显示「无法连接 embed.diagrams.net：The operation was aborted due to timeout」。

**根因**：`detectEnv()` 全量探测所有工具，其中 Draw.io 是**网络探测**（`fetch(https://embed.diagrams.net/...)`，超时 8s）。`guard()`（代码运行/语法检查的统一入口）每次 `await getEnv()`，缓存未就绪时触发全量探测 → 网络不通时每次运行前硬等 8s+。

**修复**（`server.js`）：
- `getEnv()` 默认 **skipNet**：只探测本地工具（毫秒级），运行/编译链路**永不碰网络**；网络型工具仅在环境检测界面强制刷新（`/api/env?refresh=1`）时探测。
- 网络探测超时 8s → **3s**；失败结果 **120 秒缓存**（网络不通时刷新检测不再反复等待）。
- 启动预热 `getEnv(true)` → `getEnv(false)`（本地探测即可）。

**验证**：本地环境接口 0.017s；强制刷新 0.9s；首次运行不受影响。

## 3. 局域网访问配置

- `server.js` 默认监听地址 `127.0.0.1` → **`0.0.0.0`**（任何启动方式都开放局域网；可用 `CODESCOPE_HOST=127.0.0.1` 退回仅本机）。
- 4 个启动脚本（`启动码境.command/.sh/.bat`、`start.command`）增加「局域网：http://<本机IP>:4877」提示；已运行端口被占时自动打开页面而不是报错退出。
- 注意：macOS 防火墙可能拦局域网其他设备，需允许 Node.js 接受传入连接。

## 4. 服务开关与端口占用

- 后台启动：`nohup node server.js > /tmp/codescope-4877.log 2>&1 &`（修复版默认 0.0.0.0）。
- 停止：`for pid in $(pgrep -f "node server.js"); do kill $pid; done`，确认 `lsof -nP -iTCP:4877 -sTCP:LISTEN` 无输出。
- 双击启动脚本时若提示「端口已被占用」= 已有实例在跑（不必重复启动）；脚本会直接打开页面。
- 调试 tip：`curl --noproxy '*' http://127.0.0.1:4877/api/...`（本机带代理环境必须 `--noproxy '*'`，否则请求被代理转发导致 HTTP 000 假故障）。

## 5. 依赖坑：iCloud 同步损坏 node_modules

**症状**：服务启动即崩：`TypeError: makeBufferParser is not a function`（`ssh2/lib/protocol/keyParser.js:51`）。

**根因**：vault 位于 iCloud Drive，`node_modules` 里的包文件被云盘同步机制部分清理/损坏（模块文件缺失，但 manifest 在）。

**修复**：`npm install ssh2@1.17.0 --omit=dev --no-audit --no-fund` 重装对应包即可（不用整个 `npm ci`）。注意 npm 11 的 install-scripts 提示不影响本案例。

**注意**：`node_modules` 在云盘上有损坏风险；出问题时先检查「单独 require 报错的依赖」再重装。

## 6. 调试方法论备忘

- **服务无响应定位**：`sample <pid> 3` 抓主线程调用栈（macOS）。同步 io 卡死会显示 `uv_fs_* → pread`、`execFileSync → waitpid` 等关键帧；纯空转 `uv__io_poll` 则说明事件循环活着、是某个 async 请求永不 settle。
- **区分「服务问题」vs「网络/代理问题」**：用 `curl --noproxy '*'` 直连；TCP 通但 HTTP 000、且并发请求全挂 → 事件循环被同步操作阻塞；TCP 通、HTTP 无响应但进程空转 → 请求挂在永不完成的 async 等待上。
- **云盘类根因识别**：在 iCloud/OneDrive 目录上运行的任何同步文件 IO（readdir/stat/read/copy）都可能不可中断地挂起。凡是**服务启动后开始处理某请求才**无响应的场景，优先怀疑同步 fs 读云盘文件。

## 7. 前端行为约定（防无限等待）

- `api()`（`index.html`）：统一 120s 超时；超时返回 `{ ok:false, networkError:true, error:'请求超时（后端 … 120 秒无响应）…' }`，各调用方（编译/运行/提取等）直接展示该错误文案。
- LaTeX 编译状态机：`编译中…` → `xelatex · N 页 · X.Xs`（成功）/ `编译失败` + 错误日志（失败）/ `请求超时…`（网络）。
