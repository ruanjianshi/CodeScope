### ★★★ 修掉「备忘录内容被写串」（数据损坏级）+「全部标为已读」无效 + 打开就置顶

用户报的两个问题，查下去挖出一个**静默的数据损坏 bug**：

#### ① 「本箱全部标为已读」点了没反应

- **根因**：`store()` 里写了 `UID STORE ${Number(uid)}`，而「整箱」传的是范围 `1:*` ——
  `Number('1:*')` 是 **NaN** ✗ → 拼出 `UID STORE NaN +FLAGS (\Seen)`，
  **服务器不报错、也不做事** ✗✗（界面提示成功、实际一封没标 ✗）。
- 修法：只有有限数字才转字符串，其它（范围）**原样透传** ✓，并挡掉空值 ✓。
- 实测（在「垃圾邮件」上验证，测完逐条还原 ✓）：10 封未读 → **0 封** ✓。

#### ② ★★★ 备忘录「依次点开」会**把内容写串**（数据损坏）

- **现象**：三条内容各不相同的备忘录，只是**依次点开**一遍，
  第一条的正文就变成第三条的 ✗✗。静默、无报错、看起来一切正常 ✗✗。
- **根因**：写盘目标写成了 `memoById(STORE.memoSel) || memos.filter(!trash)[0]` ✗ ——
  `memoSel` 为空时（刚进备忘录页、还没点过任何一条）会**回落到列表第一条** ✗，
  而编辑器里显示的可能是另一条 → 把 A 的正文写成 C 的 ✗。
  更糟的是有**两条** flush 路径都这么写，我上一轮加守卫时只补了其中一条 ✗（漏了 `bindMemoSide`）。
- **修法**：写盘目标收敛成**唯一入口** `memoWriteTarget()` ——
  **编辑器显示谁，就只能写谁** ✓；没有编辑器（空态）就什么都不写 ✓；**去掉危险的回落** ✗。
  三条写盘路径（切筛选 flush / 打字派生刷新 / 光标操作）全部改走它 ✓。
- 顺带修掉同一处的另一个问题：**只「打开」也会刷新 `edit` 时间戳** ✗ →
  列表会按「最新打开」重排 ✗（用户原话：「是否会自动按照最新打开的放到最上面排序，不需要这个」）。
  现在内容真的变了才更新时间戳 ✓ —— 打开不再改变顺序，真正编辑过的才会浮上来 ✓。

#### ① 卡顿：**不是渲染慢，是 IMAP 连接太多次**

先量再改：**前端同步渲染只要 8ms**（页签切换 0.5~6.9ms、点文件夹 5.7ms），
所以卡在网络上。挖出三层原因：

- **`bind()` 里 `TAB==='mail'` 就无条件 `loadMailAccounts()`** ——
  而它拉完又会 `render()` → `render()` 再 `bind()` → 再拉……**render/fetch 乒乓**。
- **`ensureMailLoad()` 用「`MAIL_UI.list` 非空」当判据** ——
  请求进行中它就是 null，于是同一个请求被反复重新发起。
- 两者叠加：**进一次邮箱页发 4×`/boxes` + 4×`/list` = 8 条 IMAP 连接**，
  每条都要新建 TLS + LOGIN（1~3 秒），所以点一下要等好几秒。

修法（前端）：
- 账号配置**只加载一次** ✓；账号没变就**不重渲染** ✓；切到邮箱页时才强制刷一次（约 10ms）。
- 所有邮件请求加**在途去重**（记「正在拉哪个 (账号,文件夹)」）✓。
- 切文件夹只请求 `list`，不再重复请求 `boxes` ✓。
- `renderMailPane()` 支持一次传多个 pane，`bindMail()` 从跑 3 遍变 1 遍 ✓。
- 标已读 / 删信后**本地改未读数并重画胶囊** ✓ ——
  以前会 `mailLoadStatus(true)`，那要对**每个账号**各开一条 IMAP 连接
  （本机到 gmail 还要等 15 秒超时），只为把一个数字减 1。

修法（服务端）：
- **新增 IMAP 连接池**（`lib/imap-client.js`）：每账号复用一条会话，
  空闲 45 秒后回收，池子上限 6；复用的会话失效时**自动重连重试一次** ✓。
  - ★ 每个账号配一个**串行队列** —— IMAP 是单命令流，
    两条命令交叉发出去响应会互相错位，而且**不报错**（数据会串）。
  - 实测：首次 434ms，之后 **64~83ms**（快 5~7 倍）；并发 4 条结果完全一致 ✓。
- **失败账号负缓存**（5 分钟）：本机连不上 gmail，以前每次刷新未读数都要等一次 TCP 超时，
  把整个 `/status` 拖到 5~15 秒；现在连不上就记下来，不再反复撞墙 ✓。
- 列表只取要显示的头部字段（去掉 TO / MESSAGE-ID）✓。

**效果**：进邮箱页的请求从 **8 条降到 2 条**；`/list` 从 2915ms → **1027ms**；
命中缓存时 13ms ✓。

### 邮箱：从「只有配置」变成**真的能收信、读信、管理邮件**

用户原话：「邮箱不是配置放着，我需要的是通过SMTP来进行邮箱的管理和查阅」。
以前这个页面只有 SMTP/IMAP 配置卡片 + 测试连接 + 发信，**收信完全没做** ——
配完什么都看不到。现在它是一个真正的收件箱。

- **新增自研零依赖 IMAP 客户端**（`lib/imap-client.js`，只用 Node 内置 `tls`/`net`）：
  `CAPABILITY` / `ID` / `LOGIN` / `SELECT` / `STATUS` / `UID SEARCH` / `UID FETCH` /
  `UID STORE` / `LIST` / `LOGOUT`；支持 993 隐式 TLS 与 143 + STARTTLS。
  - **★ 最大的坑是 IMAP 的字面量（literal）**：服务器先发一行 `* 1 FETCH (… {342}`，
    再原样吐 342 字节，然后才接着发剩下的 `)`。**不能按行读** —— 按 `\r\n` 切行的话，
    正文里的换行会把一封信切成无数行。必须按 Buffer 累积、遇到 `{n}` 精确取 n 字节。
  - **★ 第二条坑**：FETCH 的**元数据行和字面量是同一个单元**（那行以 `{n}` 结尾），
    我最初只在「行单元」里解析元数据，结果单封 `fetchHeaders(uid)` 返回空数组。
    现在按序号用 Map 合并，两种排布都认。
  - **★ 第三条坑**：未读**数量**要用 `STATUS`，不能用 `SELECT` 返回的 `[UNSEEN n]` ——
    后者是「第一封未读邮件的**序号**」，不是条数（很容易看错）。
  - 文件夹名是 **modified UTF-7**（RFC 3501），不是 UTF-8；不转换的话「已发送」「垃圾邮件」
    这类中文文件夹选不出来，而且**不报错**。
- **新增自研零依赖 MIME 解码**（`lib/mime.js`）：RFC 2047 编码词（`=?GBK?B?…?=`）、
  base64 / quoted-printable、multipart 递归、charset 别名归一。
  - **中文邮件大量是 GBK 而不是 UTF-8**，Node 自带完整 ICU，所以 `TextDecoder('gbk')` 可用。
  - quoted-printable 必须**字节级**处理 —— 先按字符串解会把多字节中文切坏。
  - 相邻编码词之间的空白要删掉（那是折行用的，不删主题里会多出空格）。
  - RFC 2231 文件名（`utf-8''%E6%8A%A5%E5%91%8A.pdf`）要按**字节**收集百分号再按声明的 charset 解码；
    用 `Buffer.from(decodeURIComponent(x), 'latin1')` 会把中文文件名截成乱码。
  - 带 `Content-ID` 的部分是**内嵌资源**（正文用 `cid:` 引用），不是附件。
- **服务端新增 6 条路由**：`/api/life/mail/status`（各账号未读数）、`/boxes`、`/list`、
  `/read`、`/part`（附件下载）、`/flag`（标记已读/未读/删除）。
  密码只在服务端 `life-mail.json` 里读，**不回传前端**；未读数与列表带 20~60 秒缓存
  （每次请求都新建 TLS 连接要 1~3 秒，顶栏还会轮询，不缓存会把邮箱服务器打爆），
  读信/改标记后立刻作废缓存。
- **前端重做成三栏收件箱**：左栏账号（带未读数）+ 文件夹，中栏邮件列表（未读圆点、
  相对时间、本地筛选框、只看未读），右栏正文阅读 + 附件下载。配置收进可折叠的「⚙ 账号配置」，
  不再是页面主体。
- **顶栏（天气那一行）新增邮箱胶囊**：显示未读总数 + 最新一封的发件人与主题，
  点击直接进邮箱页；有账号连不上时显示红色「收信失败」而不是静默无反应；
  每 120 秒静默轮询一次。
- **★ 安全：邮件正文是不可信内容，走 `sandbox=""` 的 iframe 渲染**（不带 `allow-scripts`），
  再叠一层 CSP 兜底；`<script>` 会被剥掉。**默认屏蔽远程图片**（营销邮件常用 1px 追踪像素
  回报「你什么时候打开、打开了几次」），要看图点「🖼 显示图片」。内嵌图（`cid:`）在服务端
  转成 data URL 回传（有 3 MB 总量上限），否则邮件里的插图全是破图。

### 日记：修掉「改变分类就丢失内容」

用户原话：「日记这里有问题，改变分类怎么就丢失了内容」。根因**两个**，都得修：

- **① 编辑器取的当前条目受分类筛选影响了。** 编辑器的 `cur` 是从**分类筛选后**的集合里取的 ——
  把这一篇改成别的分类后，它不再匹配当前筛选 → `cur` 变 `null` → 编辑器渲染出**空白模板**。
  用户看到的就是「内容没了」；更糟的是这时候随便打个字，600ms 防抖会把**模板**写进那一天，
  真的把原文覆盖掉。现在编辑器**按选中的日期**从全量里取条目，筛选只影响左栏日历高亮和「最近写过」列表。
- **② 自动保存是 600ms 防抖，而改分类会整屏重渲染。** `render()` 会把编辑框连同 DOM 一起重建，
  防抖还没触发 → 刚敲的字直接被冲掉。现在凡是会重建界面的日记操作（改分类 / 切日期 / 点筛选 /
  翻月 / 点「今天」/ 删除 / 切页签 / **关面板** / 切走浏览器标签）都先调 `JOURNAL_FLUSH()` 立刻落盘。
  - `JOURNAL_FLUSH` 放在**模块作用域**而不是 `bind()` 里 —— 面板关闭和 `visibilitychange` 触发时
    `bind()` 的闭包已经拿不到 DOM 了，但这两个时机恰恰最需要兜底。
  - flush 有三种情况**不写**，避免制造垃圾数据：这天本来没条目而内容只是模板/空、内容与库里完全相同、
    以及先清掉待触发的防抖定时器（否则它稍后会在**重建后的新 DOM** 上再写一次）。
- 编辑区标题现在显示**条目自己的分类**；当它不在左侧筛选范围内时补一句「（不在「X」筛选内）」，
  免得用户以为编辑器串了。
- 回归测试：`tests/browser-smoke.js` 新增日记夹具与 6 条断言（改分类后正文在屏幕上和落盘里都要还在、
  防抖未落盘时改分类不丢字、筛选别的分类时编辑器不显示模板、不重复写条目）。
  验证时**故意回退修复**确认断言会失败 —— 否则可能写出一条永远通过的空断言。
  另附独立探针 `tests/probe-journal-cat.js`（临时 vault / data，不碰真实数据）。

### 备忘录：左右实时同步 + 撤销 / 重做

用户反馈的三个问题其实是**同一个根因**：正文输入只做 600ms 防抖保存，**从不刷新派生视图**。
所以左边打字时右侧预览和左栏列表摘要都不动，要等别的操作（删除 / 切文件夹 / 点格式）触发整屏渲染才「追上来」。

- **左右实时同步**：输入时立即刷新右侧 Markdown 预览，并防抖（200ms）刷新左栏列表摘要与侧栏计数。
  刷新只碰预览和列表，**不重建 textarea** —— 否则光标、选区、浏览器原生撤销栈全丢。
  `renderMemoList()` 也补上了列表滚动位置保持（否则每打一段字列表就跳回顶部）。
- **新增撤销 / 重做**：工具栏加「↶ 撤销」「↷」（⌘Z / ⌘⇧Z，Ctrl 同理）。做法是整份备忘录的**快照栈**，
  所以删除、格式化、置顶、新建、回收站恢复都能回退；连续打字会合并成「一步」，不会每敲一个字压一帧。
  光标在输入框里时 ⌘Z 仍交给浏览器做原生文本撤销（用户预期），原生撤销也会触发 input，预览照常跟着刷新。
- **删除可撤销**：删除前会把 textarea 的最新内容收进条目、并清掉排队的自动保存（否则延迟写回会搅乱状态）。
- 顺带修掉：`B` / `I` / `U` / `S` 这些格式按钮以前改完 textarea 既不同步预览、也不落盘 ——
  「点了粗体右边没反应，切走再回来还丢了」。
- 状态位文案 `✓ 已自动保存` → `✓ 已保存`（并修掉连续提示时前一次定时器把后一次盖掉的问题）。
- **新增「导出渲染成图片」**：工具栏加「图片」按钮，把**渲染后**的正文（含标题与日期）导出成 PNG，2× 输出、深色底、自带排版（标题条 / 列表 / 引用 / 表格 / 代码块 / #标签 都按应用样式画）。预览关着也能导 —— 直接从正文现渲染一遍。
  - 实现走 SVG `<foreignObject>`：克隆渲染结果 → 用 `XMLSerializer` 转成合法 XHTML → 包进 SVG → 载成图片 → 画到 Canvas → PNG。
  - **★ 关键坑：载入 SVG 必须用 `data:` URL，不能用 `blob:` URL。** Chrome 会把「blob URL 的 SVG + foreignObject」判为跨域、Canvas 直接被污染，`toBlob` / `getImageData` 全部抛错。实测对照：blob → 污染 ✗ / data → 正常 ✓。思维导图导出的 PNG 一直做不对、只好退化成「纯 `<text>` 副本」（文字对不齐），根源就在这里。
  - 样式必须自带（外部样式表在「图片上下文」里不加载），所以导出模板把 CSS 写在 `foreignObject` 内的 `<style>` 里。
- 顺带修掉工具栏在窄屏的表现：按钮没有 `flex:none` 会被压成 28px 空壳（文字被裁掉看不清），加「图片」后 ~1100px 更是直接溢出、最右边的「删除」被裁掉点不到。现在改成**放不下就换行**，任何宽度下每个按钮都完整可点。
- **正文改成和日记一样的「逐行实时渲染」，去掉左右分栏。** 以前是「左编辑 / 右预览」两栏（还要拖中间的竖条调宽度），现在整篇就是**一个 contenteditable、每行一个 div**：光标所在行显示源码、其余行显示渲染结果，边写边看，不用左右对照。
  - 工具栏原来的「◫ 预览」开关相应改成「◫ 源码」：打开后整篇显示源码，方便整段改写或复制。
  - 打字时**不重渲染**（只存盘）—— 重渲染会把光标重置到行尾，快打时字符会跑到错误的位置。只有换行 / 点别的行 / 切源码模式才重渲染。
  - 格式按钮（B / I / U / S、标题/列表/引用…）改成作用于**光标所在行**，不再固定改第二行。
  - 修掉两个连带问题：撤销栈的「连续输入合并」只看时间，导致「新建后立刻打字」时那次编辑快照被上一步的「新建」吞掉、撤销会直接把整条备忘录退没；列表摘要在 200ms 刷新时读到的是 600ms 前的旧数据，打完字列表会少一行。

### 备忘录 / 日记：回车在光标处切分 + 行首退格不再清空内容 + 补上行号

- **行号在不同 markdown 语法下都能对齐**：标题、代码块、引用、列表的行高各不相同
  （27px / 21.85px / 23.75px…），行号原来用 `line-height: inherit` 对齐 ——
  但那些行的行高是**无单位**值（如 `1.5`），无单位值会按**伪元素自己的** `font-size`（10px）重算，
  于是行号的行盒只有 15px、正文的是 27px，**标题行的行号明显偏高**。
  现在渲染后由 `ceAlignLineNumbers()` 量出每行的实际行高写进 CSS 变量 `--ln-lh`，
  行号用它撑出等高的盒子并居中 —— 实测各语法行偏差 **0px**。备忘录和日记都生效。
- **回车现在在光标处把当前行切成两半**（后半段跟着换行），光标落在新行开头。
  以前只会「在下面插一个空行」，光标在行中间按回车时后面的文字不跟着走。
  **日记是同一套机制，一起修了。**
- **行首退格不再清空内容（严重数据丢失）**：正文是「逐行实时渲染」的 contenteditable，
  在行首按退格时浏览器会去「合并上一个块」，而上一块是 `contenteditable="false"` 的渲染行 ——
  浏览器的处理是毁灭性的：**实测按一次退格，4 行直接变 0 行**，而且空内容还被存进了服务端。
  现在自己接管行首退格 / 行尾 Delete：行首退格 = 并入上一行、行尾 Delete = 把下一行并上来；
  第一行行首 / 最后一行行尾则什么都不做（绝不能让它删）。**日记那边是同一套机制，一起修了。**
- **正文补上行号**（备忘录 + 日记）：用 CSS 计数器做，**不往 DOM 里加任何元素** ——
  所以读回源码（`readAll` / `textContent`）完全不受影响。长行折行时数字不会重复、折行文本也对齐在数字右边。
- 顺带修掉两个会让日记**整页崩掉**的健壮性问题：日记条目缺 `date` 时「最近写过」渲染会抛错；
  天气数据缺 `date` 时逐日预报渲染会抛错。现在两处都做了防护，源头也不再写出没有日期的条目。
